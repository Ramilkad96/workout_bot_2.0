# Тренер-бот (Telegram)

Бот для тех, кто хочет тренироваться по **своей** программе: пользователь
пошагово составляет программу прямо в чате, тренируется по ней (вес и
повторения по каждому подходу) и получает сводку по завершению тренировки.

## Команды

Все команды продублированы в меню Telegram (кнопка «Меню» рядом с полем
ввода) — список задаётся в `COMMANDS` в `bot.py` и ставится при запуске
через `setMyCommands`.

- `/train` — начать тренировку;
- `/program` — посмотреть программу;
- `/edit` — редактировать программу;
- `/newprogram` — составить программу заново;
- `/help` — как пользоваться ботом;
- `/cancel` — отменить текущее действие.

## Создание программы (`/newprogram`)

Пошаговый мастер:

1. сколько тренировочных дней в неделю (дни нумеруются автоматически);
2. название каждого дня — группа мышц («Грудь + трицепс»), тип тренировки
   («Фулбади»), день недели («Понедельник») или просто номер;
3. упражнение — кнопкой из каталога (8 групп мышц) или своим названием;
4. количество подходов;
5. «ещё упражнение» / «следующий день» — и так до конца программы.

В плане у упражнения хранится **только количество подходов**. Вес и повторения
не планируются заранее — они фиксируются фактически на тренировке.

## Редактирование программы (`/edit`)

- переименовать день;
- добавить и удалить день (дни автоматически перенумеровываются);
- добавить упражнение (из каталога, из личного списка или своё) и удалить его;
- изменить количество подходов;
- `💾 Сохранить день` — закрывает день и возвращает к списку дней;
- `⭐ Мои упражнения` — управление личным списком упражнений.

Изменения сохраняются сразу, выйти можно в любой момент.

## Личный список упражнений

Когда пользователь вписывает своё упражнение (в мастере или в редакторе), на
экране выбора подходов появляется переключатель «Сохранить в мои упражнения».
Сохранённые упражнения потом доступны кнопкой `⭐ Мои упражнения` рядом с
группами мышц — набирать название заново не нужно.

Список персональный (таблица `user_exercises`, ключ — `user_id`), у каждого
пользователя свой. Управление списком — в `/edit` → `⭐ Мои упражнения`:
там можно добавить упражнение вручную или удалить лишнее.

## Тренировка (`/train`)

1. выбор дня;
2. экран со списком упражнений — **порядок любой**, отмечено, что уже
   выполнено (✅), пропущено (⏭) и не начато (▫️);
3. по каждому подходу бот спрашивает сначала **вес**, затем **повторения**.
   Вес можно ввести числом или нажать кнопку: `🔁` повторить вес прошлого
   подхода, соседние веса (±2.5 / ±5 кг) или `🤸 Без веса`;
4. когда план по подходам выполнен, бот возвращает к списку упражнений;
   при желании можно снова выбрать упражнение и добавить подход сверх плана;
5. упражнение можно пропустить или завершить досрочно;
6. `🏁 Завершить тренировку` — приходит сводка и экран «Что дальше?»:
   - `✏️ Редактировать прошлую тренировку` — открывает ту же тренировку
     обратно, можно дописать подход или поправить упражнение; в истории
     остаётся одна запись, а не новая;
   - `🏋️ Начать следующую тренировку`;
   - `📋 Посмотреть программу`.

Сводка содержит дату, перечень выполненных подходов по каждому упражнению,
отметки о пропущенных и время тренировки. Тоннаж и суммарные подходы/повторения
намеренно не считаются.

Дата берётся с поправкой на часовой пояс: переменная окружения
`TZ_OFFSET_HOURS` (по умолчанию `3`, Москва) — сервер на Railway живёт в UTC.

Кнопка `✏️ Редактировать` показывается только рядом с самой программой
(`/program` и после сохранения), а не на общих экранах.

## Чистота чата

Мастер, редактор и тренировка живут **в одном сообщении**, которое бот
редактирует по ходу дела (`editMessageText`), а введённые пользователем
значения удаляются (`deleteMessage`). Ошибки ввода показываются внутри этого
же экрана, а не отдельными сообщениями. Отдельными сообщениями остаются только
важные итоги: сохранённая программа и сводка по тренировке.

Telegram не даёт ботам удалять сообщения старше 48 часов, поэтому любая
неудачная попытка удаления просто игнорируется — бот продолжает работать.

## Каталог упражнений

Каталог лежит в `catalog.py` — список групп мышц и упражнений в них.
Добавлять свои упражнения можно прямо туда, кнопки соберутся сами.
Порядок существующих записей лучше не менять (в кнопки уходят индексы),
только дописывать в конец.

Не реализовано пока (оставлено на следующие итерации):
- разбор программы через AI/LLM из свободного текста;
- сравнение факта с планом и прогресс по времени (все тренировки уже
  сохраняются в БД, так что добавить это несложно).

## Как запустить

Бот написан на чистом `requests` + long polling (без aiogram/PTB), чтобы не
зависеть от установки дополнительных фреймворков — устанавливать нужно
только `requests` и `python-dotenv`.

1. Получите токен бота у [@BotFather](https://t.me/BotFather) в Telegram
   (команда `/newbot`).
2. Скопируйте `.env.example` в `.env` и впишите токен:
   ```
   cp .env.example .env
   # откройте .env и замените BOT_TOKEN на свой
   ```
3. Установите зависимости:
   ```
   pip install -r requirements.txt
   ```
4. Запустите бота:
   ```
   python bot.py
   ```
   В консоли появится `Бот запущен: @ваш_бот`. Дальше пишите боту в Telegram.

База данных `trainer_bot.db` (SQLite) создастся автоматически рядом со
скриптом при первом запуске.

## Деплой на Railway (через GitHub, как и предыдущий бот)

Отличий от обычного деплоя python-скрипта на Railway нет — просто это не веб-
сервис, а фоновый воркер (никакого HTTP-порта слушать не нужно, бот сам
стучится в Telegram через long polling). В репозитории уже лежат нужные для
Railway файлы: `Procfile`, `railway.json`, `requirements.txt`.

1. Залейте папку `trainer_bot` в GitHub-репозиторий (файл `.env` в репозиторий
   не попадёт — он в `.gitignore`, токен туда класть не нужно).
2. В Railway: New Project → Deploy from GitHub repo → выбрать репозиторий.
3. В настройках сервиса (Variables) добавьте переменную окружения
   `BOT_TOKEN` со значением токена от @BotFather — это замена файлу `.env`,
   который используется только для локального запуска.
4. Railway сам подхватит `requirements.txt` и запустит `python bot.py` (это
   прописано в `Procfile`/`railway.json`). Никакого домена/порта настраивать
   не нужно — Health Check в `railway.json` не задан специально, чтобы
   Railway не ждал HTTP-ответ от воркера.
5. Важно: `numReplicas` в `railway.json` = 1. Long polling с двумя
   одновременными копиями бота начнёт конфликтовать (Telegram отдаёт
   обновления только одному "получателю" за раз, начнутся ошибки 409) — не
   включайте автоскейлинг/несколько реплик для этого сервиса.
6. Про базу данных: файловая система на Railway эфемерна — при каждом
   редеплое `trainer_bot.db` (а с ним все программы и история тренировок
   пользователей) обнулится. Если это важно — подключите Railway Volume
   (Settings → Volumes), примонтируйте его, например, на `/data`, и задайте
   переменную окружения `DB_PATH=/data/trainer_bot.db`. Без Volume бот будет
   работать нормально, но данные не переживут очередной деплой.
7. Часовой пояс для дат в отчётах — переменная `TZ_OFFSET_HOURS`
   (по умолчанию 3 — Москва).

## Тесты (офлайн, без сети и без Telegram)

Полный сценарий (программа → тренировка → сводка) проверен end-to-end через
фейковый Telegram API — реальная сеть не нужна:

```
python -m unittest discover -s tests -v
```

## Структура проекта

```
bot.py            — обработка команд/кнопок, точка входа и long polling
wizard.py         — пошаговый мастер создания программы (шаги и экраны)
editor.py         — редактор сохранённой программы (экраны и изменения)
workout.py        — тренировка: подходы (вес/повторы), экраны и сводка
catalog.py        — каталог упражнений по группам мышц
program.py        — структура программы и её отображение
storage.py        — SQLite: пользователи, программы, тренировки, сессии
telegram_api.py   — обёртка над Telegram Bot API (отправка, правка, удаление)
config.py         — чтение токена из .env/переменной окружения
tests/test_bot.py — офлайн-тесты мастера, редактора и тренировки (35 шт.)
```

## Почему не aiogram/python-telegram-bot

В окружении, где создавался код, не было доступа к установке пакетов из
PyPI, поэтому бот сделан на голом `requests` — это чуть больше кода, чем с
фреймворком, зато не тянет лишних зависимостей и работает предсказуемо. Если
хотите — легко переписать на aiogram (FSM там даже удобнее для такого рода
пошаговых диалогов), скажите, и я это сделаю.
